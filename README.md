# Soul Echo 灵魂回响｜SE01 规则引擎 · 组卡器 · 双人对战

面向《灵魂回响 Soul Echo》第二次修改版（0.2）与第一弹《第一声回响》的无头规则引擎、卡组构筑器与本地双人对战桌面。零第三方运行依赖，Node.js 18+ 直接运行。

## 启动

```bash
npm run dev
# http://127.0.0.1:7100/
```

| 页面 | 路径 | 用途 |
|---|---|---|
| 观战台 | `/index.html` | 脚本 AI 对 AI，生成完整对局后逐帧回放、查看连锁与卡牌 |
| 组卡 | `/deck.html` | 140 名目卡池筛选、加减卡、40—60 张校验、存读档与导入导出 |
| 双人对战 | `/duel.html` | 本地热座，双方轮流操作同一台设备，可开隐私遮罩 |

三个页面共享同一套引擎与卡池数据，改动一处三处同时生效。

## 卡池

- **140 名目主卡池**：七色＋灰各 16 张（含旧卡 53 张重印）＋混色 12 张。
- **8 张灵体**：八色各一，通用能力为「横置检视顶牌，付同色 1 可揭示」，另各有一项专属启动能力，二者共用横置。
- **2 种衍生物**：幻梦衍生物（紫）、树苗衍生物（绿，本弹仅定义）。
- 合计 **148 名目**，与 `../Soul Echo灵魂回响（以创之界限规则为灵感）/第一弹_第一声回响/` 下的卡包结构、卡表、数值审计三份文档对齐。

混色卡费用写作 `4|白2黑1/灰1`，引擎按颜色分别要求灵能；作为灵质时按第一颜色产灵能。

浏览器验收需要本机 Chrome 或 Edge，脚本自行启停服务器与浏览器，产物写入 `verification/`。

自动 AI 结果仅用于发现引擎故障与规则压力点，**不是真人胜率、平衡评级或竞技结论**。

## 12 模型 AI 脚本对阵台

12 个模型各写一份对战脚本、各自组卡，共用同一套接口约定与卡池。清单、组卡思路、对战思路与循环赛战绩见 **`agents/README.md`**。

```bash
npm run brief              # 从卡数据重新生成 agents/brief/03-卡池.md
npm run agent:check hy4    # 单份自检：语法、五导出、meta、四模式卡组、八局镜像对局
npm run agent:ladder       # 四模式循环赛，各 264 局，输出 agent-progress/ladder.md
npm run agent:swiss        # 四模式瑞士轮，各 5 届 × 5 轮，输出 agent-progress/swiss.md
```

- 脚本 = `agents/agent-<id>.js`，导出 `meta` / `deck` / `spirit` / `color` / `choose`。
- 设计说明 = `agent-progress/<id>.md`，含组卡思路与对战思路。
- 四种模式（`standard` / `blitz` / `grand` / `duo`）只改初始生命、起手与构筑上下限，回合结构不变，故同一份脚本跨模式直接可跑。

## 结构

```text
agents/                 12 份模型脚本 + 派发简报 + 循环赛结果
js/engine/cards.se01.js  SE01 全量卡数据（生成文件，来自卡表 Markdown）
js/engine/cards.js       索引层：BY_NAME / BY_ID / BY_SPIRIT，保留旧 id 别名
js/engine/precons.js     六套 40 张预组（旧卡池时代产物，保留作对照）
js/engine/effects.js     旧卡命令式效果 + SE01 分派入口
js/engine/effects.se01.js SE01 声明式效果表、静态加成、灵体能力
js/engine/rules.js       状态机、合法动作、连锁、战斗、伤害、快照
js/ai/builtin.js         只选择合法动作的确定性脚本 AI
src/main.js              观战台
src/deck.js              组卡器
src/duel.js              双人对战
server.mjs               本机静态服务器
tools/build-se01.mjs     从 SE01_卡表.md 生成 cards.se01.js
tools/fuzz-se01.mjs      随机卡组压力测试
tools/verify-se01-ui.mjs 组卡与对战浏览器验收
```

核心 API：

```js
import { createGame, legalMoves, applyMove, progressAutomatic, makeView } from './js/engine/rules.js';
import { TACTICIAN } from './js/ai/builtin.js';

const g = createGame({ deckA, deckB, spiritA: '根脉育苗者', spiritB: '雷鸣司钟人', seed: 20261113 });
progressAutomatic(g);          // 推进自动结算，直到需要玩家决策
const moves = legalMoves(g);   // 当前优先权方的全部合法动作
applyMove(g, moves[0]);
```

`makeView(g, side)` 只暴露该方手牌，是双人对战隐藏信息的基础。

## 效果层设计

旧 53 张沿用 `effects.js` 的命令式分支；SE01 新增的 95 张走 `effects.se01.js` 的声明式表：

```js
晨祷侍从: { enter: [['heal', 0, 1000]] },
净化仪式: { main: [['destroy', 0], ['destroyIfFragile', 0, 1]] },
```

每张卡的效果是一条 `[op, ...args]` 数组，由统一解释器执行，卡表文本与代码一一对应。新增卡只需加一行数据，不必再写 switch 分支。

**回响类持续效果**不写入 `mods`，而是由 `SE01_STATIC` 在面板计算时实时求值（古树牧者、森林狼王、根脉网络、钟塔守卫、雷霆战将、雷鸣穹顶），避免每回合重算漂移。

**事件钩子**（`fireHook`）覆盖六类时机：衍生物进场、卡牌进入分解区、灵像被破坏、触发效果发动、宣告攻击、每回合首次抽牌与首次使用灵感。

## 已实现规则边界

- **四种对局模式**：`standard`（生命 10／起手 4／40—60 张）、`blitz`（生命 6／起手 4）、`grand`（生命 15／起手 5／50—60 张）、`duo`（生命 12／起手 4，且须恰好 2 种非灰颜色各覆盖 ≥10 张）。模式只改初始生命、起手与构筑上下限，回合结构不变。
- 40—60 张构筑、同名最多 4、一次脚本调度。
- 先手第一回合不通常抽牌；双方各自第一回合禁止灵体通用抽牌。
- 每回合一张通常灵质；灰色灵能仅支付灰费，其他颜色可支付灰费。
- **混色费用**：按色分别要求灵能，灰费可任意颜色支付。
- 灵体检视、支付同色灵能揭示 ST、生命卡组直接抽取不触发；**八色灵体专属能力**。
- 优先权、双方连续让过、后进先出连锁、费用与目标宣告锁定、目标部分失效、反制后进分解区。
- 逐点生命伤害、LT／MT／CT、每段伤害最多追加 1 点暴击、生命为空但无后续伤害时不败。
- 单人／多人阻挡、阻挡排序、先攻、践踏、超冲击、敏捷、守护、诱饵、灵气、预制、自愈、毁灭、碾压。
- 区域切换复位、衍生物处理后移出、生命回复、预知、凝聚、灵感迸发、提取灵感、质密、墓地回收与次元超越每局限一次。
- **灵性卡**：进入战场、有生命力、可被攻击宣言指定、不能攻击或阻挡；被破坏后进入分解区。
- **激活**：揭示主卡组顶至多 X 张并发动 ST。

## 自动选择与近似口径

引擎不会静默替换未实现效果。观战台“实现范围”与 `effects.js` 的 `APPROXIMATIONS` 同步显示：

- 预知、自动触发目标与排序、葬送、结束弃牌、践踏目标和多阻挡伤害由脚本确定性选择；多阻挡按顺序分配恰好致命伤害。
- 法师护甲在生命揭示前由脚本自动替代 1 点伤害。
- **激活**：结算后保持卡组原顺序，不提供逐张置顶/置底的人工选择。
- **手牌置灵质**（幼苗守望者、部落祭司、世界树苗）自动选择当前手牌中费用最低的一张。
- **梦质处理师**：序曲“消耗梦境 2、凝聚 2”在宣告时选择减费，入场时消耗；原文时序仍需确认。
- **黑暗聚合体**：实现为质密启动后给予一次自动破坏替代，不另开替代时机响应窗。
- **亡魂役使者·伊可莱／陵园看守者**：墓地“黑色卡召唤至战场”只枚举黑色灵像。

## 卡牌数据同步

`cards.se01.js` 由 `tools/build-se01.mjs` 从 `SE01_卡表.md` 解析生成，不手工维护：

```bash
npm run build:cards
```

改卡时先改卡表 Markdown，再生成，再跑全部测试。`cards.js` 只是索引层，负责 BY_NAME / BY_ID / BY_SPIRIT 与旧 id 别名（se001—se053）。
