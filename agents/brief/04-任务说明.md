# 04 · 任务说明

## 一、你要做什么

**策略由你自己定，卡组由你自己组，脚本由你自己写。**

1. 判断《灵魂回响》SE01 环境下什么打法最有效，**自己给策略起名字**并说明理由；
2. **自己组一套卡组**（40—60 张、同名 ≤4、选 1 个灵体），并说清为什么这样组；
3. 把这套打法实现成一个零依赖 AI 脚本；
4. 写一份公开设计说明，讲清**组卡思路**与**对战思路**。

本文件与另三份简报**不提供任何策略建议**。不要问主代理「应该用什么策略」，不要参考其他模型的产物。

## 四、组卡思路（必须明确写出来）

设计说明里要有一节专讲组卡，至少覆盖：

1. **主色与灵体的选择理由**：为什么是这个颜色、这个灵体，它们提供什么你的打法需要的东西。
2. **费用曲线**：1—2 费 / 3—4 费 / 5 费以上各几张，为什么这样分布。注意「每回合只能设 1 张灵质」，这是全局最硬的限制。
3. **关键卡与张数**：哪几张是核心、投入 4 张还是 2 张、为什么。同名上限 4。
4. **颜色配比**：如果有色费要求（含混色卡），说明你怎么保证不会卡色。`duo` 模式必须给出两色各自的张数。
5. **取舍**：为什么不用某几张看起来很强的卡，或为什么宁愿少带。

卡组写进脚本的 `deck` 导出，用「卡名 → 张数」。卡名必须与 `03-卡池.md` 一字不差。

## 五、对战思路（必须明确写出来）

同一份说明里另起一节讲打法，至少覆盖：

1. **一句话胜负计划**：靠什么赢（例如「用低成本单位耗掉对方解牌，第 6 回合起用冲击 2 的单位连续打脸」）。
2. **分段计划**：前 3 回合做什么、中期做什么、什么时候切换攻防。
3. **关键决策**：手牌该不该设灵质、什么时候打脸什么时候换牌、什么时候留费用响应对方。
4. **对常见打法的应对**：面对快攻 / 控制 / 铺场各自怎么办。
5. **弱点**：这套打法怕什么，你自己认为哪里最脆弱。

## 六、硬性接口要求

严格照 `01-接口约定.md`。摘要：

1. 导出 `meta` / `deck` / `spirit` / `color` / `choose`；
2. `meta.name` 是你自起的策略名，`meta.desc` 是一句话理由，`meta.model` 与 `meta.modelId` 必须与分工表一致；
3. `choose(view, moves)` **原样返回 `moves` 里的一个元素**，不改它、不新建它；
4. 零依赖、无副作用、无模块级可变状态、必须总能返回、不得抛异常；
5. 脚本开头注释写：`策略名称` + `选择理由` + `主责模式`。

## 七、进度上报（必须）

把自己的短 id 替换进 `<id>`，分四次上报。note 要写**你自己的真实判断**，不要套模板：

```bash

```

## 八、交付前必须自检

```bash
node tools/agent-check.mjs <id>
```

**必须全部通过**才能算完成。它会检查语法、五个导出、`meta` 字段、四模式卡组合法性、四模式各两局镜像对局，并捕获脚本异常与动作循环。

如果报错是你的问题（卡名写错、卡组张数不对、choose 返回非法值），自己修。如果报错指向引擎（`rules.js`）本身的缺陷，**不要改引擎**，在汇报里写清复现步骤。

## 九、设计说明格式

`agent-progress/<id>.md`，中文，开头两行固定：

```text
执行模型 ID：<你的模型 ID>
自选策略：<你起的策略名称>
主责模式：<你的 primaryMode>
```

正文六节：

1. **策略名称与选择理由**
2. **组卡思路**（第四节要求）
3. **对战思路**（第五节要求）
4. **模式适配**：四种模式各自怎么调整，主责模式为什么最适合这套打法
5. **动作优先级**：`choose` 的打分顺序，什么分数高于什么
6. **取舍与已知弱点**

只写可审阅的设计说明，不写内部推理过程。
